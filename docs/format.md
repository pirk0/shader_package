# Пакет шейдера `shader-package/1`: правила

Пакет шейдера — папка, в которой шейдер описывает себя для хостов: вьюера, сборщика
TouchDesigner, стендов проверки. Хост не знает проекта, проект не знает хостов: между ними только
эти правила. Новый хост реализует их один раз и открывает любой пакет; новый проект пишет пакет по
ним и открывается в любом хосте.

**Обязан** — без этого пакет или хост нарушает правила. **Вправе** — хост может воспользоваться, а
может и не пользоваться: без объявления он делает полную работу, и кадр от этого не меняется.

Проверить пакет — все ошибки разом, правилом и местом:

    python check.py <папка пакета>      код 0 — ошибок нет, 1 — есть, 2 — папки нет

Проверка судит форму и имена. Правду объявлений (§4) — что пасс при `skip` и вправду не входит в
кадр — она не судит: это доказывает судья проекта. Эталоны: язык выражений — `expr.py` и векторы
`vectors/expr.json`, строка значений — `values.py`, `knobs.json` — `knobs_rules.py`. Образец —
`sample/`: на нём хосты гоняют свои стенды.

---

## 1. Пакет

Папка: описание `manifest.json`, параметры `knobs.json`, вкладки GLSL, картинки, наборы. Хост
получает папку и больше ничего.

**Пути** — относительные, через `/`, внутри папки: без `..`, без `\`, без ведущего `/` и пустых
частей. Регистр букв значим: Windows простит `Grid.png` вместо `grid.png`, веб-сервер — нет.
Раскладку внутри папки выбирает проект, хост идёт только по путям описания.

## 2. Описание `manifest.json`

| ключ | нужен | что | хост |
|---|---|---|---|
| `format` | да | `"shader-package/1"` — версия правил (§11) | незнакомую версию не открывает |
| `id` | да | `[a-z][a-z0-9_]*` | ключ хранилища, имена файлов |
| `name` | да | имя для человека; перевод `name_<код>` — по желанию | заголовок |
| `knobs` | да | путь к `knobs.json` (§8) | параметры |
| `style` | да | `"shadertoy"` — единственный в версии 1 (§2.1) | прелюдия и `main` — свои |
| `inputs` | да | входы, которые читают вкладки, из §2.1 | обязан подать каждый |
| `common` | нет | общая вкладка — перед каждой вкладкой пасса; при непустом `knobs.json` нужна | |
| `textures` | нет | картинки по именам (§3.3) | обязан исполнить |
| `buffers` | нет | буферы по именам (§3.2) | формат и очистку — обязан; `live` — вправе |
| `passes` | да | пассы по порядку исполнения (§3.1) | граф — обязан; `skip` — вправе |
| `time` | нет | значимость времени (§4.3) | вправе |
| `pointer` | нет | ручка за указателем (§4.4) | вправе |
| `let` | нет | имена для выражений (§5) | |
| `warnings` | нет | предупреждения (§5) | показать — обязан |
| `presets` | нет | папка наборов (§7.3) | вправе хранить там |
| `_comment` | нет | текст для человека | не читает |

Незнакомый ключ — ошибка, здесь и во вложенных объектах: опечатка (`"textrues"`) иначе молча выпала
бы из хоста. Тексты для человека — на языках `languages` из `knobs.json`: основное поле на первом
языке, перевод — поле рядом, `text_ru`. Нет перевода — предупреждение, хост покажет текст первого
языка; перевод на язык, которого нет в `languages`, — ошибка.

### 2.1. Стиль `shadertoy`

Вкладка пасса определяет `void mainImage(out vec4 fragColor, in vec2 fragCoord)`. Хост собирает
шейдер пасса так:

1. прелюдия: `#version 300 es`; `precision highp` у `float`, `int` и `sampler2D` — последнее не
   косметика, у `sampler2D` в ES 3.00 точности по умолчанию нет; объявления входов из `inputs` и
   `uniform sampler2D iChannel0…iChannel3`;
2. общая вкладка `common`, если есть;
3. вкладка пасса;
4. `main`, зовущий `mainImage(…, gl_FragCoord.xy)`.

Вкладки не пишут `#version`, `main` и объявлений прелюдии. Входы версии 1:

| вход | тип | значение |
|---|---|---|
| `iResolution` | `vec3` | (ширина, высота, 1) кадра в пикселях |
| `iTime` | `float` | время кадра, с |
| `iTimeDelta` | `float` | время от прошлого кадра, с |
| `iFrame` | `int` | номер кадра от 0 |
| `iMouse` | `vec4` | как у Shadertoy; привязку ручки к указателю даёт `pointer` (§4.4) |
| `iDate` | `vec4` | (год, месяц от 0, день, секунды от полуночи) |

Вкладка, читающая вход вне `inputs`, — ошибка: хост его не объявит, и шейдер не соберётся.
`iChannelResolution`, `iChannelTime`, `iFrameRate`, `iSampleRate` в версию 1 не входят.

Ручка — `uniform`, гейт — `#define` в общей вкладке (§8.6). Хост меняет гейт подменой значения в
этой строке, литералом того же типа: у целого — без точки, у вещественного — с точкой (`1.0`, а не
`1`, иначе `float x = ГЕЙТ * y;` перестанет собираться).

## 3. Пассы, буферы, картинки

### 3.1. Пасс

| ключ | нужен | что |
|---|---|---|
| `name` | да | `[a-z][a-z0-9_]*`, различны |
| `code` | да | путь к вкладке |
| `output` | да | имя буфера или `"screen"` |
| `channels` | нет | до четырёх источников по номеру `iChannelN`: имя картинки или буфера, `null` — пусто |
| `skip` | нет | пропуск (§4.1) |

Граф: на экран пишет ровно один пасс, последний; буфер пишет ровно один пасс, а читают его только
пассы после него. Обратной связи и сохранения буфера между кадрами в версии 1 нет. Вкладка,
читающая `iChannelN` при пустом канале, — ошибка; занятый канал, который вкладка не читает, —
предупреждение.

### 3.2. Буфер

| ключ | нужен | что |
|---|---|---|
| `format` | да | `rgba8` · `rgba16f` · `rgba32f`; нет такого у хоста — `rgba8` и предупреждение человеку |
| `clear` | нет | цвет RGBA, которым хост чистит буфер перед пассом каждого кадра; без ключа — `[0, 0, 0, 0]` |
| `live` | нет | область записи (§4.2) |

Размер буфера — размер кадра. Имя буфера — идентификатор, не занятый картинкой.

### 3.3. Картинка

| ключ | нужен | что |
|---|---|---|
| `file` | да | PNG или JPEG, до 8 бит на канал: 16-битный PNG хосты не читают |
| `mipmaps` | нет | `true` — цепочка уровней и трилинейная выборка; без ключа — `false`, билинейная |
| `wrap` | нет | пара по `s` и `t` из `clamp`, `repeat`, `mirror`; без ключа — `["clamp", "clamp"]` |

Хост обязан выбирать текстели как они лежат в файле, без перевода цвета (ни sRGB, ни гаммы), и
ставить картинку прямо: `uv (0, 0)` — её левый нижний угол. Шейдер, который сам называет уровень
мип-цепочки, без `mipmaps: true` читает мусор — поле существует, чтобы хост не мог этого пропустить.

## 4. Объявления хоста

Объявление — обещание проекта о своём шейдере. Проект доказывает его своим судьёй; хост вправе им
воспользоваться и судит своё исполнение на образце. Без объявления хост делает полную работу:
считает все пассы, пишет весь буфер, время значимо всегда.

### 4.1. Пропуск пасса `skip`

`"skip": [{"when": "BLUR == 0.0", "why": "…"}]`. Обещание: при истинном `when` выход пасса в кадр
не входит. Хост вправе не считать пасс и оставить в буфере прежнее содержимое. `why` — для
человека, читающего описание: почему пасс не нужен. Пасс на экран не пропускается.

### 4.2. Область записи `live`

`"live": ["x", "y"]` — два выражения в пикселях. Обещание: пасс не пишет пиксель с центром `F`, где
`F.x > x` или `F.y > y`, и там буфер не читает никто. Хост вправе растеризовать и чистить только
`floor(x − 0.5) + 1` столбцов и `floor(y − 0.5) + 1` строк от левого нижнего угла.

### 4.3. Время `time`

`"time": {"when": "…", "help": "…"}`. Обещание: кадр зависит от `iTime`, только когда `when`
истинно — или когда значение текстового гейта уведено от дефолта и называет `iTime` (формулу
гейта проект не знает заранее). Хост вправе не перерисовывать стоящий кадр и не писать `ITIME` в
строку значений (§7). `help` — подсказка человеку, когда время входит в кадр.

### 4.4. Указатель `pointer`

`"pointer": [{"knob": "SPOT"}]` — не длиннее одного. Ручка — `vec2` с `ui: origin` и диапазоном
`[0, 0]…[1, 1]`: точка кадра. Хост вправе водить её указателем: доля кадра от левого нижнего угла,
зажатая в `[0, 1]`. Подсказку указателя хост строит из `label` ручки.

### 4.5. Пустое объявление

Объявление пусто, если имени из его выражения нет ни в `knobs.json`, ни в объявлениях общей вкладки:
описание отстало от шейдера. Пустое объявление хост не исполняет — делает полную работу, а
предупреждение с пустым условием не показывает; описание он называет отставшим. Имя, которое есть
в шейдере, но не в `knobs.json`, пустоты не даёт: значение берётся из шейдера (§8.7).

## 5. Предупреждения и `let`

`"warnings": [{"id", "when", "short", "text"}]`. При истинном `when` хост обязан показать `text`;
`short` — строка для тесного места, по желанию. `id` — `[a-z][a-z0-9_]*`, различны. Тексты —
шаблоны: `{выражение}` хост заменяет числом по §6.5; фигурные скобки в тексте — только шаблоны.

`"let": {"nx": "max(floor(COLS + 0.5), 1.0)"}` — имена для условий, областей и шаблонов. Имя `let` —
идентификатор, не занятый ручкой, гейтом или входом; `let` не ссылается на `let`. Тип имени — тип
его выражения (§6.2).

## 6. Язык выражений

Подмножество выражений GLSL ES 3.00: проект пишет формулу так же, как в шейдере. Правила типов
повторяют GLSL, поэтому выражение, которое принимает проверка, собирается GLSL с тем же типом —
на векторах это подтверждает glslang (§6.6). Обратное неверно: часть выражений GLSL язык не
берёт намеренно (§6.2).

### 6.1. Синтаксис

- числа: целые `0`, `12` и вещественные `1.0`, `.5`, `1.`, `2.5e-1`, `1e3`;
- имена ручек, гейтов, `let` и `iResolution`; компонента `.x .y .z`;
- функции `floor ceil abs min max mod clamp float`;
- унарные `+ - !`, бинарные `* / + - < <= > >= == != && ||`, скобки.

Приоритет и ассоциативность — GLSL: унарные, затем `* /`, `+ -`, сравнения, `== !=`, `&&`, `||`.

### 6.2. Типы

| имя | тип |
|---|---|
| ручка | `float`, `vec2`, `vec3` по `type`; вектор — только с компонентой |
| гейт-список | `int` |
| гейт-число | тип литерала его `#define`: с точкой или порядком — `float`, иначе `int` |
| текстовый гейт | в выражении — ошибка: его значение — формула, а не число |
| `iResolution` | `vec3` |
| имя `let` | тип его выражения |

Неявных преобразований нет, как в GLSL ES 3.00: `BLUR == 0` — ошибка, нужно `BLUR == 0.0`;
`float(MAX_DOTS)` переводит целое. Функции — с перегрузками GLSL: `floor`, `ceil`, `mod` — у
`float`; `abs`, `min`, `max`, `clamp` — у `float` и у `int`; `float` — у `int`, `float`, `bool`.
`&&`, `||`, `!` — у `bool`.

Строже GLSL намеренно: деления целых нет — GLSL отбрасывает дробь, а хост считает в двойной
точности, и `7 / 2` дало бы 3.5 вместо 3; нет восьмеричной и шестнадцатеричной записи, суффикса
`f` и целых больше `2147483647`.

Нужный тип: `when` у `skip`, `time` и предупреждений — `bool`; `live` и шаблоны — `int` или
`float`; `let` — любой из трёх.

### 6.3. Значение

Хост считает в двойной точности и типов не знает: у выражения, прошедшего проверку, ответ тот же,
что с типами.

- **Ручка** — то, что получит шейдер: число хоста, округлённое до float32. **Гейт** — значение его
  `#define`. `iResolution` — (ширина, высота, 1).
- `bool` — 1 или 0. Сравнения — по IEEE-754: с NaN ложны все, кроме `!=`.
- Деление на ноль — по IEEE: ±inf, `0/0` — NaN. `min`, `max` с NaN — NaN.
  `mod(x, y) = x − y·floor(x/y)`. `floor`, `ceil` сохраняют знак нуля.
- Обе стороны `&&` и `||` считаются всегда: пустоту объявления (§4.5) решают имена, а не значения.

### 6.4. Точность

Шейдер считает во float32, хост — в двойной точности. Объявление, чей ответ решает середина
float32 (`floor(x + 0.5)` ровно на половине), у хоста и шейдера может разойтись на ULP. Проект пишет
объявления так, чтобы этого не было, а его судья это доказывает; хост float32 не эмулирует.

### 6.5. Числа в тексте

Целое по модулю меньше 10¹⁵ — без точки: `35`, `-0` пишется `0`. Иначе — шесть значащих цифр, как
`%g` у printf: хвостовые нули и точка убираются; показатель — если десятичный порядок меньше −4
или не меньше 6, вида `1.23457e+06`, `1.234e-05`; ровно посередине — к чётной (`123456.5` →
`123456`). Особые — `NaN`, `inf`, `-inf`.

### 6.6. Векторы

`vectors/expr.json` — договор для каждой реализации языка: значение и тип, пустота, ошибки
синтаксиса и типа, шаблоны, float32. Эталон проходит их на стенде `tests/vectors_check.py`; там же
glslang подтверждает, что язык — подмножество GLSL.

## 7. Строка значений и наборы

### 7.1. Строка

Токены `ИМЯ=ЗНАЧЕНИЕ` через пробел, только отличия от дефолтов. Так её отдаёт хост и принимает
стенд, и так лежит набор. Строка задаёт состояние целиком: чего в ней нет, то берётся дефолтом.

- Токен, в котором есть что-то кроме букв, цифр и `_ . + = -`, пишется в одинарных кавычках
  целиком: `'SPOT=vec2(0.35,0.6)'`, `'EDGE(d)=1.0 - step(0.0, d)'`. Так он литерален и в bash, и в
  PowerShell.
- Разбор терпимый: из любого текста берутся токены с `=`, имя — до первого `=`. Остальное
  возвращается вызывающему непонятым, а не глотается молча.

### 7.2. Имена и значения

| имя | значение |
|---|---|
| ручка `float` | число |
| ручка `vec2`, `vec3` | `vecN(a,b,…)` без пробелов; читатель вправе принять и `a,b,…` |
| гейт-список, гейт-число | значение `#define` |
| текстовый гейт `ИМЯ(x)` | формула как есть, имя — с аргументами |
| `ИМЯ_deg` | поле угла `ui: angle` и `ui: deg` (§8.4), градусы |
| `ИМЯ_color`, `ИМЯ_amount` | поле `ui: tint` (§8.4): цвет `vec3` и сила |
| `ITIME` | время кадра, с — только когда время значимо (§4.3) |
| `@имя` | состояние хоста (масштаб, анимация); чужой хост пропускает его и называет |

Число — литерал, который читается обратно в то же число двойной точности. Незнакомое имя хост
называет непонятым и не падает: набор мог пережить переименование. `ITIME` — имя строки, поэтому
ручка и гейт так называться не могут (§8.8).

### 7.3. Наборы

Папка `presets` из описания. Набор — файл `<имя>.txt`: строки с `#` в начале — комментарии,
остальные склеиваются пробелом в одну строку значений. Папки может не быть: её создаст хост при
первом сохранении.

Имя набора — путь внутри папки без `.txt`, через `/`: подпапки законны, частей в имени не больше
трёх (`demo/wide grid` — две). Части — по правилам путей §1. Хост показывает наборы всех подпапок
и сохраняет набор с `/` в имени в подпапку.

## 8. Параметры `knobs.json`

`knobs.json` — единый источник параметров шейдера: по нему хост строит поля и подаёт значения.

### 8.1. Ручки и гейты

| | ручка, `knobs` | гейт, `gates` |
|---|---|---|
| в шейдере | `uniform float/vec2/vec3 ИМЯ;` | `#define ИМЯ значение` |
| смена значения | без перекомпиляции | перекомпиляция всех пассов |
| поле хоста | на каждую компоненту | список, число или строка |

Непрерывная величина — ручка. Структурная ветка (режим, другой алгоритм, потолок цикла) — гейт, и
его дефолт воспроизводит прежнее поведение. Ветку нельзя выключать ручкой: обнулить эффект ручкой
— не значит не считать его, экономит только гейт.

### 8.2. Верхний уровень

```json
{ "_comment": "…", "languages": [["en", "English"], ["ru", "Русский"]],
  "titles": {"SPOT": "Spot"}, "titles_ru": {"SPOT": "Пятно"},
  "pages": [{"name": "Spot", "name_ru": "Пятно", "groups": ["SPOT"]}],
  "knobs": [ … ], "gates": [ … ] }
```

- Других ключей нет — ни здесь, ни в записях: незнакомое поле — ошибка. Порядок записей ничего не
  значит, порядок полей задаёт `order`.
- **`languages`** — пары (код из 2–3 строчных латинских букв, название), коды различны. Первый язык
  — язык основных полей (`label`, `help`, `options`, `notable`, `name` страницы) и выбор хоста по
  умолчанию. Перевод — поле рядом: `label_<код>`, `help_<код>`, `options_<код>`, `notable_<код>`,
  у страницы `name_<код>`; у `options` и `notable` — те же значения в том же порядке, меняется
  текст. Перевод подчиняется правилам основного текста. Без `languages` файл одноязычный. Нет
  перевода — предупреждение; поле на необъявленный язык — ошибка.
- **`titles`** и `titles_<код>` — названия групп и подгрупп на языке; хост ищет `titles_<код>`,
  затем `titles`, затем само имя. Название группы, которой нет, — предупреждение.
- **`pages`** — надгруппы, по желанию. Без них хост ставит страницу на группу. С ними каждая группа
  записей стоит ровно в одной странице, имена страниц различны, порядок страниц — порядок вкладок
  хоста. Группа в `pages` без записей — предупреждение.

### 8.3. Ручка

| поле | нужно | значение |
|---|---|---|
| `name` | да | идентификатор GLSL, имя `uniform` |
| `type` | да | `float` · `vec2` · `vec3` |
| `default` | да | число или список из 2–3 чисел; равен `// =…` в шейдере |
| `min`, `max` | да | той же формы; `min ≤ default ≤ max` покомпонентно |
| `group` | да | раздел — папка или заголовок над полями |
| `sub` | нет | подраздел, строчными: иначе его заголовок не отличить от заголовка группы |
| `label` | да | короткая подпись, различная внутри группы — у ручек и гейтов вместе |
| `help` | нет | подсказка: одна строка до 100 символов — что делает и в каких единицах |
| `order` | да | целое ≥ 0, сквозное и различное среди ручек и гейтов |
| `ui` | нет | преобразование хоста (§8.4) |
| `angle`, `tint` | при `ui` | блок своего `ui` (§8.4), ровно при нём |
| `periodic` | нет | период > 0: края диапазона дают один кадр; у вектора — только при `ui: angle`, в градусах |
| `probe`, `notable` | нет | точки паспорта (§8.9) |

Диапазон — границы поля, а не запрет: выйти за него осознанно законно, а молча упереться в край —
нет. В `help` — без истории проекта: дат, хешей, ссылок, слов «раньше». Длинное описание живёт в
комментарии шейдера (§8.6).

### 8.4. `ui`

| `ui` | тип | поле хоста | в шейдер уходит | правило |
|---|---|---|---|---|
| `angle` | `vec2` | угол в градусах: границы и дефолт — блок `angle {default, min, max}` | `vec2(cos α, sin α)` | `default` — это `(cos, sin)` угла `angle.default` с точностью 10⁻⁶, иначе хосты начнут с разного поворота |
| `deg` | `float` | угол в градусах: запись × 180/π | то же число в радианах | границы живут один раз, в радианах записи |
| `tint` | `vec3` | цвет (белый в начале) и сила — блок `tint {amount, amount_max}` | `(1 − цвет) · сила` | `default` — нулевой вектор; `0 ≤ amount ≤ amount_max` |
| `origin` | `vec2` | точка кадра в `[0, 1]²` | та же пара | не больше одной ручки на пакет |

### 8.5. Гейт

| поле | нужно | значение |
|---|---|---|
| `name` | да | идентификатор GLSL или макрос `ИМЯ(x)` |
| `default` | да | значение `#define` по виду; равно значению в шейдере |
| `group`, `sub`, `label`, `help`, `order` | как у ручки | гейт стоит перед своими ручками |
| `kind` | нет | нет поля — список; `number` — число; `text` — формула |
| `options` | у списка | `[[целое, «подпись»], …]`, две пары и больше, значения различны, `default` среди них |
| `min`, `max`, `step` | у числа | числа; `min ≤ default ≤ max`, `step > 0` |
| `probe`, `notable` | нет | как у ручки; у текста значение — формула |

Вид держит ровно свои поля: список — только `options`, число — только `min/max/step`, текст — ни
одного из четырёх. Гейт с `options` и `kind: "number"` разом хосты прочли бы по-разному. Значение
текстового гейта — непустая строка без переноса.

### 8.6. Объявления в шейдере

Ручки и гейты объявляются в общей вкладке, по одному разу, и только там: вкладка пасса, объявившая
их ещё раз, не соберётся.

    uniform vec2  SPOT;   // =vec2(0.5, 0.5)  центр пятна, доля кадра
                          // продолжение описания — строками комментария ниже
    #define PULSE_MODE 0  // 0 пятно неподвижно | 1 радиус пульсирует

- У ручки `// =дефолт` стоит сразу после `;` и равен `default` число в число. Без него ручка, от
  которой отстал `knobs.json`, получит 0: инициализатора у `uniform` в GLSL ES 3.00 нет.
- Ровно одно `#define` на гейт: хост подменяет значение в этой строке (всё от имени до `//` или
  конца строки), второе объявление — это `Macro redefined`.
- Литерал гейта-списка — целое. Гейт-число с целым литералом держит целые `min`, `max` и `step`:
  дробный шаг хост подставил бы дробью, и тип гейта сменился бы.
- `uniform` в общей вкладке без записи в `knobs.json` — ошибка пакета: хост не знает, что ему подать.
- Описание параметра — остаток комментария и строки-продолжения `// …` ниже; обрывают его пустая
  строка, строка кода или заголовок `// ---`.

### 8.7. Отставание: хост и неполный `knobs.json`

У проверки пакета расхождение `knobs.json` с шейдером — ошибка. Хост же обязан пережить его: не
ронять панель, а назвать расхождение по имени.

- **гейта нет в json** — шейдер работает со значением `#define` из файла, поля нет;
- **ручки нет в json** — поля нет, значение — из `// =…` у объявления;
- **записи json нет в шейдере** — поле лишнее, хост его не создаёт.

### 8.8. Имена

Имя — идентификатор GLSL; у гейта допустимо `ИМЯ(x)`. Имена различны среди ручек и гейтов вместе.
Заняты прелюдией и строкой значений: входы §2.1, `iChannel0…3`, `mainImage`, `main` и `ITIME`.

### 8.9. Точки паспорта

- **`notable`** — `[[значение, «подпись»], …]`: значение, где параметр меняет не силу, а смысл.
  Лежит внутри `[min, max]`, иначе поле до него не доедет. Хост показывает его в подсказке.
- **`probe`** — точка проверки параметра у стендов проекта; хост её не читает. Вне диапазона —
  только с причиной третьим элементом `[значение, «подпись», «причина»]`, внутри — без неё.

## 9. Чего версия 1 не выражает

- обратной связи, сохранения буферов между кадрами и буферов не во весь кадр (у ISF это есть —
  войдёт версией 2);
- видео, звука, кубических карт, больше одной точки за указателем;
- зависимости ручки от гейта и диагональных условий (`COLS · ROWS ≤ 64`: паспорт — коробка, а не
  область);
- типов `int`, `bool`, `vec4` и цвета у ручек — цвет бывает только как `ui: tint`.

## 10. Новый проект: порядок действий

1. **Шейдер.** Вкладки Shadertoy: общая с объявлениями (§8.6) и по вкладке на пасс. Структурная
   ветка — гейтом с путём назад.
2. **`knobs.json`.** Запись на объявление, `order` — по порядку полей, у ручки — `min/max` поля, у
   гейта — вид, у каждой — `help`.
3. **`manifest.json`.** Пассы, буферы, картинки и `inputs` — по тому, что читают вкладки;
   объявления (§4) — только те, что проект докажет своим судьёй; предупреждения — где кадр при
   известных значениях неверен.
4. **Проверка — после каждой правки:** `python check.py <папка>` даёт ноль ошибок.

## 11. Версии правил

`format` называет версию. Хост не открывает пакет незнакомой версии. Уточнение остаётся версией 1,
только если каждый пакет, верный до него, остаётся верным и значит то же самое; иначе — новая версия
`shader-package/2`, и хост называет, какие версии знает.
