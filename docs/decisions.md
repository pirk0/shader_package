# Решения правил

Что выбрано или отклонено и почему. Принятое не переписывают: замена — новой строкой, у старой —
статус и ссылка на неё. Правила выросли из предложения `research/journal/shader_manifest.md` проекта
`liquid_glass` (коммит `34112fc` там): разбор, прецеденты (ISF, Shadertoy) и замер черновика — в нём.

| решение | дата | основание |
|---|---|---|
| Правила пакета шейдера живут в отдельном репо `shader_package`: договор не принадлежит ни проекту, ни хосту | 2026-10-21 | решение пользователя: хосты не знают проекта, проект не знает хостов, а правила «где-то должны быть утверждены для организации синтаксиса и переиспользования в дальнейших проектах». Место — ответ «Создал этот репо» на §10 предложения |
| Описание — `manifest.json`, версия правил — `"format": "shader-package/1"` | 2026-10-21 | ответ пользователя «Поддерживаю» на §10 предложения |
| Картинки и наборы лежат в пакете, путь к ним задаёт описание, хост берёт их по описанию; раскладку внутри пакета выбирает проект | 2026-10-21 | решение пользователя: «Ассеты изображений, связанные с шейдером, должны остаться с шейдером. Вьюер и сборщик в тд должны подхватывать такие ассеты.» |
| Предупреждения хоста — объявление пакета: условие на языке выражений и текст-шаблон | 2026-10-21 | решение пользователя: «Предупреждения должны остаться, но быть регламентированы правилами… при определенных значениях параметров и гейтов шейдеры могут отображаться некорректно.» |
| Язык выражений — подмножество выражений GLSL; дерево JSON и виды предупреждений без языка отклонены | 2026-10-21 | ответ пользователя «Делай как рекомендуешь» на §10 предложения: формулу проект пишет тем же языком, что шейдер; дерево пришлось бы сверять с GLSL переводом, а виды без языка требовали бы правки правил на каждое новое условие |
| Язык типизирован, как GLSL ES 3.00: `int`, `float`, `bool`, без неявных преобразований, `when` — `bool`; деления целых, восьмеричной и шестнадцатеричной записи, суффикса `f` нет. Замещает семантику черновика без типов (истина — `≠ 0`, сравнение даёт 1 или 0) | 2026-10-21 | моё уточнение при переносе в правила: в черновике `7 / 2` давало 3.5 при 3 у GLSL, а `1 && 0` было законно, хотя GLSL его не примет — формула, перенесённая из шейдера, меняла бы смысл молча. Правила типов повторяют перегрузки GLSL ES 3.00; на векторах glslang это подтверждает (`tests/vectors_check.py` блок 6), а хост считает в двойной точности без типов, и ответ тот же. Описание `liquid_glass` из черновика проходит проверку без правок |
| Общая часть правил `knobs.json` — здесь; как файл читает конкретный хост — у хоста. Блок `px` в версию 1 не вошёл | 2026-10-21 | моё решение: параметры — часть пакета, и проверка пакета без них неполна. Правила взяты из `docs/format.md` инструмента пульта TouchDesigner (`animation_knobs_parser`, коммит 547a85d) — пометка «общее»; блок `px` — соглашение одного проекта, его гейт снят там 2026-10-21. До переноса сборки TouchDesigner на пакет правила `knobs.json` живут в двух местах (`docs/tasks.md`) |
| Расхождение `knobs.json` с шейдером — ошибка проверки пакета; хост его переживает и называет (§8.7) | 2026-10-21 | у кнопок инструмента пульта отставание — предупреждение, у его стенда — ошибка; пакет проверяют перед выпуском, и отставать ему незачем |
| Ручки и гейты объявляются в общей вкладке; пакет с параметрами без неё — ошибка | 2026-10-21 | моё решение: подмена `#define` и сверка `// =дефолт` идут по одному тексту, а вкладка пасса со вторым объявлением не соберётся |
| Тип гейта-числа в выражении — тип литерала его `#define`; целый литерал требует целых `min`, `max`, `step`; хост подставляет значение литералом того же типа | 2026-10-21 | моё решение: GLSL типизирует гейт по литералу, а хост, шагнувший дробью или записавший `1` вместо `1.0`, сменил бы тип, и шейдер перестал бы собираться |
| Указатель водит одну ручку `vec2` с `ui: origin`; список в описании — на вырост | 2026-10-21 | моё решение: `ui: origin` уже ограничен одной ручкой; несколько точек — версия 2 |
| Набор — файл `<имя>.txt` со строкой значений; поля хоста по правилам `ui` (`_deg`, `_color`, `_amount`) входят в строку, состояние хоста — токены `@имя`; время — `ITIME`, имя занято | 2026-10-21 | моё решение: иначе набор, сохранённый одним хостом, другой не прочёл бы. Грамматика — кавычки, терпимый разбор, комментарии `#` — как у наборов вьюера `liquid_glass`, где она судится возвратом состояния и кадра; `ITIME` — как у его стенда `render_glsl.py` |
| Числа в тексте шаблона — `%g` с шестью значащими, ровно посередине — к чётной; целое — без точки | 2026-10-21 | черновик говорил «до шести значащих», и две реализации разошлись бы на `123456.5`: `toPrecision` JavaScript по спецификации ECMAScript берёт из двух ближайших большее, printf — чётное (замерен только printf, через Python). Векторы держат правило |
| Проверка пакета судит форму и имена, а не правду объявлений; правду образца судит `tests/sample_check.py` | 2026-10-21 | правду объявления доказывает судья проекта на его шейдере — проверке правил шейдер не исполнить; образец — проект этого репо, и его судья здесь |
| Наборы в подпапках законны: имя набора — путь внутри папки `presets` без `.txt` через `/`, не больше трёх частей; проверка обходит папку рекурсивно. Плоская папка с запретом `/` в имени отклонена | 2026-10-21 | решение пользователя проекта `liquid_glass` («а)» на вопрос перед переводом его вьюера на пакет): вьюер сохраняет набор `демо/широкая сетка` в подпапку, а версия 1 знала только плоскую папку. Правка оставлена версией 1, хотя по букве §11 меняет смысл пакета с подпапкой в `presets`: прежде подпапка давала лишь предупреждение «хосты не прочтут», теперь её наборы проверяются и показываются. Пакетов с подпапками наборов на день правки нет — у единственного проекта папка наборов пуста |
